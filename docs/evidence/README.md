The browser test fails if the two-viewer interruption exceeds 500 ms. Its timing is a local sample, not an OBS capture or production network benchmark. Node tests separately advance an injected clock through playback deadlines and far beyond the old scene's end, checking that stale playback cannot return. Browser tests also check refresh recovery and offline board/clock retention.

Chromium screenshots were visually reviewed at 1080p and 720p. OBS itself, an eight-hour rehearsal and the PRD's five-person comprehension check have not been run. Node's built-in SQLite currently emits an experimental-feature warning on the local runtime; the application otherwise runs without runtime warnings of its own.

## Read the captures together

1. Compare the thinking and spotlight frames. The clocks keep their screen coordinates, and the last actual move stays at 9...h6. A rank or percentage belongs to the labelled engine. The lower strip records moves the players actually made.
2. Compare spotlight and interruption. Once 10.d4 is played, the large board and move strip advance together. The previous root’s +0.35, 30/50/20 percentages and candidate rows must all disappear, even though d4 was also the first hypothetical move.
3. Compare 1080p and 720p. Read the header, clocks, move numbers and WDL labels without hovering. Confirm the active clock and hypothetical state can each be identified without colour alone.
4. For motion, run the browser test or watch both cues in the local programme. A still image cannot show whether a transition replayed on a clock tick or whether an old animation obscured the first frame after release.
